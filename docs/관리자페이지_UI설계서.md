## 2. 공통 레이아웃 규칙

모든 관리자 화면은 아래 뼈대를 공유한다 (`common.css` 기준).

```
┌─────────────────────────────────────────────┐
│ 상단바 (전체 폭 — 탭 메뉴, 관리자 정보)             │
├───────────────┬───────────────────────────────┤
│               │                               │
│  지도 (40%)    │        패널 (60%)              │
│  테두리+둥근모서리│  페이지별 콘텐츠(표/폼/카드)      │
│               │                               │
└───────────────┴───────────────────────────────┘
```

- **상단바**: 화면 최상단 고정, 전체 폭. 5개 탭(대시보드/제보관리/피드백관리/마커등록/도시정보) + 관리자 닉네임 + 로그아웃
- **지도 영역**: 좌측 40%, 카드형 박스로 안착. 제보/피드백/도시정보 테이블의 "지도이동" 아이콘 클릭 시 해당 좌표로 이동(의도)
- **패널 영역**: 우측 60%, 페이지 목적에 따라 표/필터/폼 배치
- **디자인 톤**: 그림자 없는 플랫 스타일, 1px 얇은 테두리, 채도 낮은 배경색, Tabler 아이콘(웹폰트), sentence case 라벨

## 4. 화면별 상세

### SC-01. 관리자 대시보드

**목적**: 활성 제보/누적 피드백/등록된 도시정보 건수를 한눈에 확인

**주요 UI 요소**
- 요약 지표 카드 3개 (활성 제보, 누적 피드백, 등록된 정보)
- 각 카드에 "오늘 +N" 증감 표시

**연관 API**: `GET /admin/summary` — 활성 제보/누적 피드백/등록된 도시정보 건수 및 오늘 증감 집계 (별도 테이블/뷰 없이 요청 시점 COUNT 집계)

---

### SC-02. 관리자 — 제보 관리

**목적**: 전체 제보를 필터링하여 조회하고 상세 확인, 삭제

**주요 UI 요소**
- 필터바 (유형, 기간, 활성여부) + 조회/초기화
- 제보 테이블 (지도이동 아이콘, 유형, 작성자, 설명, 작성일, 활성여부, 상세/삭제)
- 페이지네이션
- 상세 모달 (좌표, 설명 전문, 미니맵, 첨부사진, 삭제)

**연관 API**
- `GET /admin/reports` — 목록 조회 (필터 포함)
- `DELETE /admin/reports/{id}` — 삭제

**상태/예외**
- 비활성(만료/삭제) 행은 회색 처리, 상세만 가능하고 삭제 버튼 비노출

---

### SC-03. 관리자 — 피드백 관리

**목적**: 전체 피드백을 필터링하여 조회, 상세 확인, 삭제

**주요 UI 요소**
- 필터바 (체감안전도, 기간, 활성여부, 검색어)
- 피드백 테이블 (지도이동 아이콘, 작성자, 격자ID, 체감안전도 배지, 한줄평, 태그, 사진유무, 작성일, 활성여부, 상세/삭제)
- 페이지네이션
- 상세 모달 (한줄평 전문, 태그, 격자 중심 미니맵, 첨부사진, 삭제)

**연관 API**
- `GET /admin/feedbacks` — 목록 조회 (필터 포함)
- `DELETE /admin/feedbacks/{id}` — 소프트 삭제(`is_active='N'`)

**비고**: 좌표는 피드백 자체가 아닌 **소속 격자의 중심좌표**를 사용 (피드백은 격자 단위 등록이라 정확한 지점 좌표가 없음)

---

### SC-04. 피드백 삭제 확인

**목적**: 삭제 전 최종 확인, 소프트 삭제임을 안내

**주요 UI 요소**
- 확인 문구 + "소프트 삭제 — 목록에서 비활성 처리" 안내
- 대상 요약 (작성자 등)
- 취소/삭제 버튼

**연관 API**: `DELETE /admin/feedbacks/{id}`

---

### SC-05. 관리자 — 마커 등록

**목적**: 관리자가 지도에 제보 유형 또는 도시정보 유형 마커를 직접 등록

**주요 UI 요소**
- 마커 유형 선택 (제보 5종 + 도시정보 3종 통합 드롭다운)
- 좌표 입력 (지도 클릭 연동 또는 직접 입력)
- 제목/설명
- 시작/종료 시각 (도시정보 유형일 때 노출)
- 사진 첨부(선택)
- 등록/초기화 버튼

**연관 API**: `POST /admin/markers` — 유형에 따라 `report` 또는 `city_events` 테이블로 자동 라우팅

**상태/예외**
- 좌표 미지정 시 등록 비활성화 (API명세서 예외처리와 일치)

---

### SC-06. 관리자 — 도시정보 관리

**목적**: 등록된 행사/인파밀집/교통통제 정보를 조회하고 삭제

**주요 UI 요소**
- 필터바 (유형)
- 도시정보 테이블 (지도이동 아이콘, 유형, 제목, 기간, 등록일, 상세/삭제)

**연관 API**
- `GET /admin/city-events` — 목록 조회
- `DELETE /admin/city-events/{id}` — 삭제
