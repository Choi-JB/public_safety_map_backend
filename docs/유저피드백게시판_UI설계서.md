## 2. 공통 레이아웃 규칙

`common.css` 기준 공통 뼈대를 따른다.

```
┌─────────────────────────────────────────────┐
│ 상단바 (전체 폭 — 격자명/선택정보, 유저 정보)         │
├───────────────┬───────────────────────────────┤
│               │                               │
│  지도 (40%)    │        패널 (60%)              │
│  테두리+둥근모서리│  체감안전도 요약 + 피드백 목록    │
│               │                               │
└───────────────┴───────────────────────────────┘
```

- **지도 영역**: 좌측 40%, 현재 선택된 격자 위치에 마커 표시
- **패널 영역**: 우측 60%, 체감안전도 요약 카드 + 태그 카드 + 피드백 목록
- **디자인 톤**: 그림자 없는 플랫 스타일, 1px 얇은 테두리, 채도 낮은 배경색, sentence case 라벨

## 4. 화면별 상세

### SC-01. 유저 피드백 게시판

**목적**: 특정 격자의 체감안전도 비율, 태그, 피드백 목록을 열람하고 등록 화면으로 진입

**진입 경로**
- (경로 A) 지도 메인 화면에서 "피드백 게시판" 버튼 클릭 → 격자 선택 모드로 전환 → 지도에서 원하는 구역 클릭 → 해당 격자의 게시판 표시
- (경로 B) 지도 인포카드(FN-01-04)에서 특정 격자 선택 → "피드백 더보기" 등으로 진입

두 경로 모두 최종적으로 동일한 SC-01 화면(해당 grid_id 기준)으로 연결됨

**주요 UI 요소**
- (경로 A 진입 시) 좌측 지도에 "구역을 선택하세요" 안내 힌트 표시 (admin-markers 화면의 select-hint 패턴 재사용)
- 체감안전도 비율 카드 (안전/보통/불안 배지 + 비율 바)
- 태그 클라우드 카드
- 정렬 토글 (최신순/추천순)
- 피드백 카드 목록 (작성자, 작성일, 체감안전도 배지, 한줄평, 태그, 사진 유무)
- 본인 작성 피드백에 한해 수정/삭제 버튼 노출

**연관 API**
- `GET /grids/{grid_id}/feedbacks` — 목록 조회
- `GET /grids/{grid_id}/detail` — 체감안전도 비율/태그 요약

**상태/예외**
- 비회원: "피드백 남기기" 클릭 시 로그인 유도 (화면 자체는 열람 가능)
- 피드백 없음: "아직 이 구역에 남겨진 피드백이 없어요. 첫 피드백을 남겨보세요" 안내 문구 + 등록 버튼 표시

### SC-02. 피드백 등록/수정 폼

**목적**: 체감안전도, 한줄평, 태그, 사진(1장)을 입력해 피드백을 등록하거나 본인 피드백을 수정

**진입 경로**: SC-01 "피드백 남기기" 버튼 클릭 시, 먼저 `GET /grids/{grid_id}/feedbacks/me`로 본인 작성 피드백 존재 여부 확인 → 있으면 수정 폼(값 채워서), 없으면 등록 폼으로 진입 (사용자는 어느 쪽이 열렸는지 폼 제목으로만 구분)

**주요 UI 요소**
- 위치 정보 (읽기 전용 — 격자 변경 불가 안내 문구)
- 체감안전도 3단 선택(불안/보통/안전)
- 한줄평 입력
- 태그 다중 선택 (체크박스형)
- 사진 첨부 (1장, 파일선택 + 미리보기 + 제거)
- 등록/취소 버튼

**연관 API**
- `GET /grids/{grid_id}/feedbacks/me` — 진입 시 사전 확인 (신규/수정 분기)
- `POST /grids/{grid_id}/feedbacks` — 신규 등록
- `PATCH /feedbacks/{id}` — 본인 피드백 수정 (img_url null 전송 시 사진 삭제)

**상태/예외**
- 사전 확인으로 중복 등록 자체를 차단하는 것이 기본 흐름. 동시 요청 등 예외적으로 409가 발생하면 "이미 이 구역에 남긴 피드백이 있어요. 새로고침 후 다시 시도해 주세요" 안내
