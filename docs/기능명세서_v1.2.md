## 3. 기능별 상세 명세

### FN-01-01. 치안 위험 지역 정보 표시

**개요**
지도 화면에 치안 관련 인프라(CCTV, 보안등, 소방시설, 파출소·경찰서, 편의점 등) 정보를 격자 단위로 시각화한다.

**사전조건**
- 앱 최초 진입 시 위치 권한 허용 상태 (미허용 시 기본 위치로 대체)

**처리 흐름**
1. 앱/웹 진입 시 유저 현재 위치를 중심으로 지도 초기 표시
2. 현재 화면(viewport)에 포함된 격자 목록 계산
3. 서버에 해당 격자들의 인프라 데이터만 요청 (화면 밖 데이터는 조회하지 않음)
4. 지도 위에 아이콘/오버레이 형태로 렌더링
5. 사용자가 지도를 이동/줌 할 때마다 새로 화면에 들어온 격자만 추가 조회

**입력 데이터**

| 항목명 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 위도/경도 범위 | Float(bounding box) | Y | 현재 지도 화면의 좌표 범위 → 포함 격자 계산에 사용 |
| 표시 항목 필터 | Array | N | CCTV / 보안등 / 소방시설 / 파출소·경찰서 / 편의점 등 선택 필터 |

**출력/화면 요소**

| 요소 | 설명 |
|---|---|
| 지도 오버레이 아이콘 | CCTV, 보안등, 소방시설, 파출소·경찰서, 편의점 위치 마커 |
| 범례(Legend) | 아이콘 종류 안내 |
| 필터 버튼 | 인프라 종류별 On/Off 토글 |

**예외 처리**

| 상황 | 처리 방안 |
|---|---|
| 위치 권한 미허용 | 기본 위치(예: 서울시청) 기준으로 표시 + 권한 요청 안내 팝업 |
| 공공데이터 API 응답 실패/타임아웃 | 캐시된 최근 데이터 표시 + "최신 정보 아님" 안내 문구 |
| 해당 격자 데이터 없음 | "해당 지역은 정보가 제공되지 않습니다" 안내 |

### FN-01-02. 실시간 도시 정보 제공

**개요**
대형 행사, 인파 밀집 지역, 교통 통제 구역 등 실시간 도시 정보를 지도에 표시한다.

**처리 흐름**
1. 외부 API(지자체 등) 또는 관리자 직접 등록(FN-05-01 연계) 데이터 수신
2. 지도상 해당 격자(들)를 하이라이트(색상 오버레이) 처리
3. 클릭 시 상세 정보(행사명, 시간, 통제 구간) 팝업 표시

**입력 데이터**

| 항목명 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 이벤트 유형 | Enum | Y | 행사/인파밀집/교통통제 |
| 발생 격자/좌표 | Polygon/Point | Y | 영향 범위 |
| 시작/종료 시각 | Datetime | N | 알 수 있는 경우만 |

**출력/화면 요소**
- 격자 하이라이트 오버레이(색상 구분)
- 상세 정보 팝업 (행사명, 예상 인파, 교통통제 구간, 시간)

**예외 처리**

| 상황 | 처리 방안 |
|---|---|
| 실시간 데이터 소스 장애 | 마지막 수신 데이터 유지 + 갱신 시각 표시 |
| 종료 시각 경과 후 미갱신 | 자동으로 지도에서 제거(만료 처리) |

### FN-01-03. 긴급 피난처 표시

**개요**
우범지역 인근 대피 가능 장소(파출소, 24시간 편의점 등)를 지도에 표시한다.

**처리 흐름**
1. 화면에 표시된 격자 중 치안 위험 등급이 일정 수준 이상인 격자 판별
2. 반경 내 피난처(파출소/편의점) 데이터 조회
3. 지도에 피난처 아이콘 표시

**입력 데이터**

| 항목명 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 피난처 유형 | Enum | Y | 파출소 / 24시간 편의점 / 기타 |
| 좌표 | Float | Y | 위도/경도 |
| 운영시간 | String | N | 24시간 여부 등 |

**출력/화면 요소**
- 피난처 전용 아이콘(파출소/편의점 구분)
- 클릭 시 상세정보(주소, 운영시간, 거리)

**예외 처리**

| 상황 | 처리 방안 |
|---|---|
| 반경 내 피난처 없음 | 반경을 단계적으로 확대하여 재검색, 그래도 없을 시 "인근 피난처 없음" 안내 |

### FN-01-04. 구역별 상세 인포카드 (안전등급 포함)

**개요**
지도상 특정 격자 선택 시, 해당 구역의 안전 정보를 카드 형태로 제공한다.

**처리 흐름**
1. 사용자가 지도 상 격자(마커/영역) 탭
2. 서버에 해당 격자 상세 정보 요청
3. 하단 시트(Bottom Sheet) 또는 팝업 카드로 정보 표시

**안전등급 산정 로직**
- 산정 기준: 해당 격자 내 인프라(CCTV, 보안등, 소방시설, 파출소·경찰서, 편의점 등) 개수 단순 합산
- 가중치 없음 (모든 인프라 항목 동일 비중)
- 등급 구간(threshold) 값은 추후 데이터 확보 후 튜닝

**입력 데이터**

| 항목명 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 격자 ID | String | Y | 선택된 격자 식별자 |

**출력/화면 요소**

| 요소 | 설명 |
|---|---|
| 태그 목록 | `#가로등_많음`, `#유흥가_주변` 등 |
| 안전 등급 | 등급(예: 안심/보통/주의) + 색상(초록/노랑/빨강)으로 표시. 숫자 점수는 미사용 |
| 목적지까지 안전정보 | 현재 위치~목적지 구간 요약 정보 |
| 체감안전도 요약 | 유저 피드백(FN-03-01)의 `불안/보통/안전` 응답 비율을 표시 (예: 안전 60% · 보통 30% · 불안 10%) |
| 최근 한줄평 미리보기 | FN-03-01 연계 |

**예외 처리**

| 상황 | 처리 방안 |
|---|---|
| 신규/데이터 부족 격자 | "아직 충분한 정보가 없습니다" + 정보 등록 유도 |

> **용어 정리**: 기존 "평점(1~5점)" 방식 대신, 유저가 체감하는 안전 수준을 **`불안 / 보통 / 안전`** 3단계 중 선택하는 방식으로 변경. 이 항목의 명칭은 **"체감안전도"**로 통일 표기 (FN-01-04, FN-03-01 공통 적용).

### FN-02-01. 돌발 상황 제보 등록/수정/삭제 *(앱 전용)*

**개요**
지도에 미표기된 돌발 상황(교통사고, 싱크홀, 재해, 공사 등)을 사용자가 직접 등록한다. 회원만 이용 가능.

**처리 흐름 - 등록**
1. 사용자가 '제보하기' 버튼 탭 (비로그인 시 로그인 유도)
2. 위치는 현재 위치 자동 획득만 가능 (지도에서 수동 선택 불가)
3. 제보 유형 선택 + 사진 첨부(선택) + 상황 종료 예정시간 입력(선택)
4. 등록 요청 → 검수 없이 서버 저장 즉시 → 지도 즉시 반영
5. 자동 만료 타이머 설정(기본 24시간)

**처리 흐름 - 수정/삭제**
1. 본인이 작성한 제보 목록(마이페이지 등)에서 항목 선택
2. 작성자 본인에 한해 수정 또는 삭제 가능
3. 관리자는 전체 제보에 대해 삭제 권한 보유 (FN-05-01 참고)

**입력 데이터**

| 항목명 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 제보 유형 | Enum | Y | 교통사고/싱크홀/자연재해/공사/기타 |
| 좌표 | Float | Y | 제보 시점의 현재 위치(GPS)로 자동 설정, 수동 변경 불가 |
| 사진 | Image (1장) | N | 선택 첨부, 여러 장 업로드 불가 |
| 종료 예정 시각 | Datetime | N | 미입력 시 기본 만료정책 적용 |
| 상세 설명 | Text | N | 최대 글자수 제한 (예: 200자) |

**출력/화면 요소**
- 제보 작성 폼 화면 (앱 전용)
- 등록/수정/삭제 완료 토스트
- 지도 내 제보 마커(유형별 아이콘)

**예외 처리**

| 상황 | 처리 방안 |
|---|---|
| 비회원 접근 | 로그인 화면으로 이동 |
| GPS 수신 실패/위치 획득 불가 | 등록 버튼 비활성화 + "현재 위치를 확인할 수 없습니다" 안내, 재시도 유도 |
| 사진 용량 초과 | 클라이언트단 리사이징 후 업로드, 초과 시 안내 메시지 |
| 네트워크 실패 | 로컬 임시 저장 후 재전송 옵션 제공 |
| 스팸성 반복 제보 | 동일 유저 단시간 내 다중 등록 제한(Rate Limit) |
| 타인 게시물 수정/삭제 시도 | 권한 없음 처리, 버튼 비노출 |

**비고**: 검수 프로세스는 도입하지 않음 (즉시반영). 신뢰도 검증 기능은 Phase 2(FN-04-03)로 이관.

### FN-02-01-R. 제보 마커 열람 *(앱 + 웹)*

**개요**
등록된 제보를 지도 상에서 조회한다. 비회원도 열람 가능.

**출력/화면 요소**
- 지도 내 제보 마커 (앱과 동일한 형태로 웹에도 노출)
- 마커 클릭 시 상세정보 팝업 (읽기 전용, 웹에서는 등록/수정/삭제 버튼 비노출)

### FN-02-02. 긴급 위험 알림 (Push Notification) *(앱 전용)*

**개요**
유저 신고, 관리자 등록 도시정보, 또는 국가 재난문자 연동 정보를 기반으로 인근 사용자에게 푸시 알림을 발송한다. 비회원도 수신 가능.

**처리 흐름**
1. 신규 제보 등록, 도시정보(city_events) 등록, 또는 재난문자 API 수신
2. 발송 기준 판단 (아래 표 참고)
3. 발송 대상 사용자 필터링 (로그인 여부 무관, 위치 기반)
4. 푸시 알림 발송

**발송 반경 기준**

| 알림 유형 | 발송 기준 |
|---|---|
| 유저 제보 기반 알림 | 유저 위치 기준 반경 500m 고정 |
| 관리자 등록 도시정보(행사/인파밀집/교통통제) | 이벤트 좌표 기준 반경 500m 고정 (추후 이벤트 규모별 조정 가능) |
| 국가 재난문자 연동 | 국가 재난문자 발송 기준을 그대로 따름 (별도 반경 설정 없음) |

**입력 데이터**

| 항목명 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 알림 유형 | Enum | Y | 유저제보 / 재난문자 |
| 알림 내용 | Text | Y | 제목 + 요약 |

**출력/화면 요소**
- 모바일 푸시 알림 (앱 전용, 웹 미지원)
- 알림 탭 시 해당 위치로 지도 이동

**예외 처리**

| 상황 | 처리 방안 |
|---|---|
| 알림 권한 미허용 | 인앱 배너로 대체 노출 |
| 과도한 알림 발생(중복 제보 다수) | 동일 사안 그룹핑하여 1건으로 통합 발송 |

### FN-03-01. 구역별 유저 피드백 게시판

**개요**
사용자가 특정 격자에 대해 체감안전도, 한줄평, 태그, 사진 등을 등록/열람/수정/삭제할 수 있는 게시판. 열람은 비회원 가능, 작성은 회원만.

**처리 흐름**
1. 인포카드(FN-01-04)에서 '피드백 남기기' 진입 (비로그인 시 로그인 유도)
2. 체감안전도(불안/보통/안전) 선택 + 한줄평 + 태그 선택 + 사진(선택) 입력
3. 등록 → 해당 격자 피드백 리스트에 반영 → 체감안전도 비율 갱신
4. 작성자 본인은 자신의 피드백에 한해 수정/삭제 가능

**입력 데이터**

| 항목명 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 격자 ID | String | Y | |
| 체감안전도 | Enum | Y | `불안` / `보통` / `안전` 중 택1 |
| 한줄평 | Text | Y | 최대 글자수 제한 |
| 태그 | Array | N | 사전 정의된 태그 중 선택 |
| 사진 | Image (1장) | N | 선택 첨부, 여러 장 업로드 불가 |

**출력/화면 요소**
- 피드백 목록(최신순/추천순 정렬) - 앱/웹 공통 열람
- 체감안전도 비율 그래프 + 태그 클라우드

**예외 처리**

| 상황 | 처리 방안 |
|---|---|
| 비회원의 작성 시도 | 로그인 화면으로 이동 |
| 비속어/도배성 게시 | 금칙어 필터링 + 신고 기능 |
| 중복 평가 방지 | 동일 유저-동일 격자 평가는 수정만 가능(재등록 불가) |
| 타인 게시물 수정/삭제 시도 | 권한 없음 처리, 버튼 비노출 |

### FN-05-01. 관리자 페이지 *(웹 전용)*

**개요**
운영자가 유저 제보/피드백을 관리하고, 지도 위에 마커를 직접 생성할 수 있는 관리 화면.

**계정 정책**
- 별도 관리자 계정 1개로 운영 (일반 회원 계정과 분리)

**세부 기능 ① - 제보/피드백 관리**

처리 흐름:
1. 관리자 로그인 (일반 회원 로그인과 별도)
2. 전체 제보 목록 / 전체 피드백 목록 조회 (필터: 유형별, 날짜별 등)
3. 부적절한 게시물 선택 후 삭제

| 요소 | 설명 |
|---|---|
| 제보 관리 테이블 | 전체 제보 목록, 상세보기, 삭제 버튼 |
| 피드백 관리 테이블 | 전체 피드백 목록, 상세보기, 삭제 버튼 |

**세부 기능 ② - 마커 직접 등록 (신규)**

**개요**
관리자 계정에 한해, 지도 위에 새로운 마커를 직접 생성할 수 있다. FN-02-01(유저 제보)과 동일한 마커 형식을 사용하며, 특히 대형 행사(FN-01-02) 등 외부 API 연동 없이 관리자가 즉시 등록하는 것이 더 빠른 정보는 이 기능으로 직접 추가한다.

**처리 흐름**
1. 관리자 페이지에서 지도상 위치 클릭(또는 좌표 직접 입력)으로 마커 생성 시작
2. 마커 유형 선택 (제보 유형 or 대형행사/통제구역 등 FN-01-02 유형)
3. 상세 정보 입력(제목, 설명, 사진, 기간 등) 후 등록
4. 등록 즉시 지도에 반영 (앱/웹 동일 노출)

**입력 데이터**

| 항목명 | 타입 | 필수 | 설명 |
|---|---|---|---|
| 마커 유형 | Enum | Y | 제보유형(교통사고 등) 또는 도시정보유형(행사/통제구역 등) |
| 좌표 | Float | Y | 지도 클릭 또는 직접 입력 |
| 제목/설명 | Text | Y | |
| 사진 | Image | N | 선택 첨부 |
| 유효 기간 | Datetime | N | 미입력 시 수동 삭제 전까지 유지 |

**출력/화면 요소**
- 마커 등록 폼 (지도 클릭형 위치 선택 UI 포함)
- 등록된 마커는 일반 유저 화면에 일반 제보/도시정보 마커와 동일하게 노출

**권한 정책**
- 도시정보(행사/인파밀집/교통통제, FN-01-02)는 **등록과 삭제 모두 관리자 전용**. 일반 유저는 열람만 가능하고 직접 등록/삭제할 수 없음 (제보와의 차이점)
- 관리자 페이지에서 등록된 전체 도시정보 목록을 조회하고, 종료되었거나 잘못 등록한 항목을 삭제할 수 있음

**예외 처리**

| 상황 | 처리 방안 |
|---|---|
| 일반 계정으로 관리자 페이지 접근 시도 | 접근 차단, 권한 없음 안내 |
| 좌표 미지정 | 등록 버튼 비활성화 |
